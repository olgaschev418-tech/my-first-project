# Как устроены блоки

В Scratch откройте `Monster_AI_Lab.sb3`. Выберите **Сцену** — там находятся правила. Выберите **Искрик** — приветствие, костюмы и реакции. **Кнопки** только передают сообщения. Это помогает найти причину ошибки: вход → правило → изменение числа → реакция.

## Переменные

| Переменная | Значение / назначение |
|---|---|
| Сцена | 0 — комната, 1 — бой, 2 — победа, 3 — поражение, 4 — финал |
| Здоровье / Энергия | 0–100; начальные значения 100 и 50 |
| Сила / Уровень / Опыт | 10 / 1 / 0; сила до 24, новый уровень каждые 50 опыта |
| Раунд | 1, 2, 3 — выбранный соперник |
| Здоровье врага | `20 + Раунд × 40`: 60, 100, 140 |
| Ход | 0 — можно действовать, 1 — действие обрабатывается |
| Защита | 1 — уменьшить ближайший ответный удар, затем снова 0 |
| Счётчик ходов | Число ответов врага в текущем бою |
| Урон | Обычный ответ: `7 + Раунд × 3`; каждый третий +15; под щитом 3 |
| Имя / Победы | Выбранное имя и число побед в этом запуске |

`Сцена` и `Ход` — две разные переменные. Первая отвечает, **где** мы играем, вторая — **можно ли уже нажать ещё раз**.

## Три коротких алгоритма для начала

Это текстовое описание стандартных блоков; дети собирают его в редакторе, а не вставляют как код.

### Кормление

```text
когда я получу [Кормить]
если <<Сцена = 0> и <Ход = 0>> то
  задать Ход = 1
  изменить Энергия на 20
  если <Энергия > 100> то задать Энергия = 100
  изменить Здоровье на 10
  если <Здоровье > 100> то задать Здоровье = 100
  ждать 0.3 секунд
  задать Ход = 0
```

Для первых уроков можно сначала сделать только прибавление энергии и ограничение 100; блокировку хода добавляем позже.

### Тренировка

```text
когда я получу [Тренировать]
если <<<Сцена = 0> и <Ход = 0>> и <Энергия > 9>> то
  задать Ход = 1
  изменить Энергия на -10
  если <Сила < 24> то изменить Сила на 2
  изменить Опыт на 10
  передать [Уровень+] и ждать
  ждать 0.3 секунд
  задать Ход = 0
```

В `Уровень+`: если опыт больше 49, отнять 50, уровень увеличить на 1. За одно событие здесь добавляется не больше 30 опыта, поэтому хватает одного `если`. Если дети добавят награду 150, предложите заменить проверку циклом до уменьшения опыта ниже 50.

### Атака

```text
когда я получу [Атака]
если <<<Сцена = 1> и <Ход = 0>> и <Энергия > 7>> то
  задать Ход = 1
  изменить Энергия на -8
  изменить Здоровье врага на (0 - (Сила + Уровень * 2))
  если <Здоровье врага < 1> то
    задать Здоровье врага = 0
    передать [Победа] и ждать
  если <Сцена = 1> то передать [Ответ врага] и ждать
  задать Ход = 0
```

Почему проверяем сцену перед ответом? Если враг побеждён, он больше не отвечает. Почему «передать **и ждать**»? Чтобы следующий ход не начался, пока текущий не завершён.

## Сообщения и клавиши

`Кормить / f`, `Тренировать / t`, `Отдых / r`, `Арена / b`, `Атака / a`, `Защищаться / d`, `Лечение / h`, `Домой / q`. Внутренние сообщения: `Ответ врага`, `Победа`, `Уровень+`.

Кнопка имеет три простых скрипта: по щелчку передать сообщение; по клавише передать то же сообщение; постоянно показывать/прятать себя по сцене. Изменение чисел находится на Сцене, а не дублируется в каждой кнопке. Реакция питомца декоративная: если неподходящее действие заблокировано, короткая реплика может всё равно появиться; значения переменных определяются только правилами Сцены.

## Подключение камеры

```text
изображение камеры
    ↓ MediaPipe Hands — готовая нейросеть
21 точка руки
    ↓ стартовые правила ИЛИ kNN на примерах ребёнка
Атака / Щит / Лечение
    ↓ удержание + пауза для защиты от случайных повторов
клавиша A / D / H
    ↓ те же блоки Scratch, что у обычной кнопки
правило игры
```

Веб-плеер не меняет здоровье сам. Он передаёт виртуальную клавишу в Scratch VM. Поэтому действие проходит те же проверки энергии, сцены и хода.

При изменении учебного `.sb3` оставляйте исходные переменные, их имена и сообщения; **не удаляйте переменные и не создавайте их заново**, иначе изменятся идентификаторы. Изменять значения, рисунки, числа урона, порядок блоков и подписи кнопок можно. Новые переменные тоже можно добавлять. Если нужна совершенно другая структура проекта, адаптация плеера — задача преподавателя или разработчика, а не обязательная детская часть.

## Где искать файлы разработчику

`web/game/*.sb3` — то, что открывают дети. `web/gestures.mjs` — короткий классификатор и защита от повторов. `web/app.js` — загрузка Scratch и камера. `tools/build_project.py` — упаковщик проекта, а не обязательный материал для учеников. Он **перезаписывает эталонные `.sb3`** при сборке; детские работы храните под другими именами и вне `web/game`.
