# Проверки комплекта

Среда: Linux, Node.js 24.19.0, Python 3.12.14, Playwright 1.56.1 и системный Chromium. Дата: 19 октября 2026.

Версия 2.1 включает готовое распознавание руки MediaPipe Hands. `npm run test:camera` проверяет настоящую локальную WASM-нейросеть на искусственной камере без руки; затем отдельно проверяет преобразование контрольных точек руки в игровые команды. Контрольные точки в этой второй проверке синтетические: это не проверка качества нейросети на реальных детских руках.

## Что проверяется автоматически

Команды из папки monster-protocol: `npm run generate`, `npm run export`, затем `npm run serve` и в другом терминале `npm test`.

- Оба JSON-проекта импортируются настоящим ядром **GDevelop 5.6.269** и экспортируются в HTML5. Нет ошибок выражений или неизвестных типов ресурсов. В браузере работают экспортированные события GDevelop; отдельной HTML-копии правил нет.
- Генерация повторяется с теми же SHA-256 обоих game.json. Ресурсы ML не добавляются повторно как изображения. Экспорт очищает только свой build-каталог, чтобы не накапливать старые файлы.
- 10 категорий: выбор назад/вперёд и переход через край диапазона. Два MonsterEyes получают одинаковую анимацию. Выбор героя переносится между сценами.
- Имя, локальное сохранение, изменение/возврат внешности и загрузка после перезагрузки страницы. Некорректное сохранение не заменяет текущие значения.
- Кормление ограничено 100; пять тренировок из полной энергии дают силу 30 и нулевую энергию; следующая тренировка отклоняется. Уровень увеличивается после трёх тренировок.
- Пошаговый бой: щит, расход энергии, три последовательные победы, финал и новая кампания. Основная кампания пройдена реальными UI-щелчками без подстановки победных характеристик.
- Поражение/восстановление отдельно проверяются с намеренно установленными граничными Health=1 и Energy=0. Это отдельный проверочный сценарий, а не способ пройти кампанию.
- MediaPipe Hands, WASM и веса загружаются локально и выполняют инференс: искусственная камера без руки не вызывает команды.
- Отдельные фикстуры 21 точки проверяют кулак → атака, ладонь → щит, два пальца → лечение; один палец и отсутствие руки не вызывают команду. Эти фикстуры проходят тот же обработчик результатов, что реальная нейросеть, но не подменяют проверку распознавания физических рук.
- Удержанный кулак не повторяет атаку после ответного хода; после убранной руки следующая команда разрешена. Проверяются реальные события атаки, щита и лечения GDevelop.
- Камера запускается одним нажатием, окно меньше 260 px, фона-затемнения нет; обычные кнопки доступны. Окно передвигается. Проверяются закрытие, повторное включение, выключение той же кнопкой, остановка всех видеодорожек и отказ в разрешении камеры.
- Ученический шаблон запускается отдельно: готовы только BodyNext/EyesNext, остальные события действительно оставлены как задания. Проверяется ввод после изменения размера окна до 1366×768.
- Собираются журналы ошибок страницы, неуспешных ресурсов и внешних запросов. Проверка требует пустых журналов; во время локальной игры и модели внешняя сеть не используется.
- ZIP проверяются по CRC, наличие всех ресурсов и относительность путей проверяются внутри каждого упакованного проекта. Готовая игра запускается также после распаковки демонстрационного ZIP, через поставляемый Python-сервер.

Результат актуального запуска тестов — `docs/validation-result.json`; снимки — в docs/images. Разработческие подробные логи и временные файлы не включены в ученический проект.

## Что автоматический тест не подтверждает

- Физическую школьную камеру, реальные руки, освещение, конкретные ноутбуки и качество пользовательской модели. Проверить до занятий 6–7.
- Windows/macOS, их диалоги разрешений и установленный редактор на школьном устройстве. Файлы переносимы по структуре; фактическое открытие в школе — отдельная проверка преподавателя.
- Доступность сайта обучения Teachable Machine в школьной сети. Локальный экспорт не проверяет доступ к внешнему сайту.
- Универсальную точность распознавания руки. Физическую камеру, освещение, ориентацию руки и жесты ребёнка нужно проверить на школьном устройстве.
- Полноценное преподавание курса группе в реальном темпе. План рассчитан на готовую графику/интерфейс/адаптер, содержит обязательный минимум и дополнительные задания; темп первого набора нужно измерить.

## Как повторить перед раздачей

Распакуйте студенческий архив на другом школьном ноутбуке, откройте project/game.json в GDevelop, измените одну деталь и сохраните. В демо пройдите один бой кнопками, затем проверьте свою модель и выключение камеры. Не заменяйте эти проверки наличием зелёного результата облачных тестов.

## Исправление запуска Windows

После сообщения пользователя о фрагментах команд `-3`, `rorlevel`, `n` исправлен START_WINDOWS.bat: ASCII без BOM, окончания строк CRLF, кавычки вокруг путей и проверка Python 3.10+. Упаковщик принудительно сохраняет CRLF независимо от настроек Git и проверяет байты внутри ZIP. `npm run test:windows-launcher` проверяет формат и переходы. Сам cmd.exe в этой Linux-среде недоступен; выполнение на Windows не заявляется проверенным.

## Версия 2: живой мир и постановка боя

Дополнительные проверки: движение героя в покое; реальное воспроизведение локальной музыки и выключатель; поглаживание; три разных имени/иллюстрации хранителей; последовательный ответ с задержкой; реальный усиленный урон 24 у финального хранителя; награды, покупка улучшения дома и сохранение трофеев при новой кампании. Повторные клики во время хода блокируются.

`node tests/assisted.mjs` воспроизводит маршрут преподавателя: отдельная копия ученического JSON, UseBattleScaffold=1 и три добавленных обычных события кнопок в 04.2. Эта копия экспортируется ядром GDevelop. Проверяются блокировка второго нажатия в замахе, предупреждение о сильном ударе, щит с уроном 3, награда и финал. Начальные характеристики этой короткой проверки заданы намеренно; полная демонстрационная кампания отдельно проходится UI-тестом без подмены характеристик.

Живые эффекты используют позиции, заданные в редакторе; тесты проверяют движение, но художественная привлекательность и подходящий темп — предмет просмотра преподавателя, а не автоматическая оценка. Музыка проверяется через воспроизведение аудиоэлемента в браузере; динамики конкретного школьного ноутбука проверяются на месте.

Учебная программа обновлена на 8 × 90 минут. Поминутный план, игры без компьютера и Word-файлы проверены по структуре и ссылкам; фактический темп группы ещё предстоит оценить на первом проведении. Это изменение учебных материалов, игровые сцены и логика не менялись.
