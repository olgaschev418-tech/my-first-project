# Лабораторная работа № 3 — Множественное наследование

**Шевченко О.Н. · ВИИМ21 · Вариант 2**  
Профиль: «Искусственный интеллект и математическое моделирование».

Оформление отчёта основано на лабораторной № 2: сохранены титульный лист,
поля и стили. Цель, задания, выполнение, иллюстрации, листинги и вывод
заменены на содержание лабораторной № 3.

## Что входит в работу

- `ЛР3_Шевченко_ОН_вариант_2.docx` — редактируемый отчёт.
- `ЛР3_Шевченко_ОН_вариант_2.pdf` — отчёт с фиксированной вёрсткой.
- `programs/task1_employees.py` — сотрудники, полиморфный список,
  множественное наследование и явное разрешение конфликта методов.
- `programs/task2_layers.py` — Layer, DenseLayer, ConvolutionalLayer,
  Dense и Conv; forward, backward и MRO.
- `programs/analytics_core.py` — полная общая часть задания 2: базовый класс,
  четыре миксина, kNN-регрессия, подбор k по leave-one-out MSE, метрики,
  ROI, гибридный анализатор, super(), MRO и обработка исключений.
- `programs/test_lab3.py` — 14 автоматических тестов.
- `example_report.json` — результат реального экспорта аналитического отчёта.
- `assets/` — иллюстрации, исходники диаграмм Graphviz и полные протоколы.
- `validation.txt` — результаты тестов и консольных проверок.
- `tools/` — вспомогательные скрипты генерации иллюстраций и Word-отчёта.

## Запуск

Нужен Python 3.10 или новее. Программы и тесты используют только стандартную
библиотеку; установка сторонних пакетов не требуется.

Из каталога `lab3_shevchenko`:

```sh
python3 programs/task1_employees.py
python3 programs/task2_layers.py
python3 programs/analytics_core.py
python3 -m unittest discover -s programs -v
```

В Windows вместо `python3` можно использовать `python`.
Демонстрационные данные находятся в функциях `main()` соответствующих
программ; при запуске вводить что-либо не требуется.

## Контрольные результаты

Для `x = [1, 2, 3, 4, 5]`, `y = [100, 200, 300, 400, 500]`:

| Показатель | Результат |
| --- | --- |
| LOO MSE, k = 1 | 10000 |
| LOO MSE, k = 2 | 9000 |
| LOO MSE, k = 3 | 18666,67 |
| Выбранное k | 2 |
| MAE / RMSE на обучающих данных | 50 / 50 |
| Прогноз для x = 6 | 450 |
| Затраты | 300 |
| ROI | 50 % — прибыль |

Равные расстояния в kNN разрешаются по исходному порядку записей.
Метрики на обучающих данных не оценивают обобщающую способность;
LOO отдельно используется для выбора k. kNN за границей обучающего
диапазона усредняет ближайших соседей, а не продолжает линейный тренд.

Слои нейросети возвращают строки согласно варианту: численное обучение
нейросети в этой части не требуется. В общих требованиях ядра ML реализовано
отдельным kNN-регрессором. Миксины кэша и журнала имеют служебное состояние;
самостоятельно не используются.

Идентификаторы уникальны внутри своего семейства объектов в одном процессе.
Поэтому id гибридного объекта в полном запуске (после двух других компонентов)
равен 3, а в отдельно сгенерированном JSON — 1.

## Как устроен MRO

```text
HybridAnalyzer → MLModel → EconomicIndicator → ValidationMixin
→ CachingMixin → LoggingMixin → ReportMixin → BaseComponent → object
```

`super()` обращается к следующему подходящему классу в этом порядке.
Общий предок инициализируется один раз. `init_trace` показывает порядок
завершения конструкторов после возврата из `super()`, поэтому не совпадает
с направлением поиска по MRO.

## Повторная сборка отчёта

Для вспомогательных инструментов нужны `python-docx`, Pillow, Graphviz,
LibreOffice и шрифты DejaVu в стандартном Linux-пути. Эти зависимости
не нужны для решения лабораторной и тестов.

Из каталога `lab3_shevchenko`:

```sh
python3 tools/make_assets.py
python3 tools/make_report.py
soffice --headless --convert-to pdf --outdir . ЛР3_Шевченко_ОН_вариант_2.docx
```

Шаблон по умолчанию — готовый Word-отчёт лабораторной № 2 в соседней папке
репозитория. Другой путь можно передать параметром `--template`.
Текст снимков экрана получен реальным запуском программ. В рисунке 1
цепочки MRO перенесены на несколько строк для читаемости; полный исходный
вывод сохранён в текстовом файле.
